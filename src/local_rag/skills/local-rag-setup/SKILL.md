# Set up local-rag-mcp

Complete the operator's requested setup through the installed CLI. Carry forward supplied inputs
and authorization, perform routine work autonomously, and ask only for required missing inputs.
Do not turn optional OCR, embeddings, or background indexing into mandatory questions.

## Locate and inspect

Read [references/runtime.json](references/runtime.json), generated by `install-skills`, for absolute
`cli`, `python`, `mcp_server`, and the original nonsecret `package_source`. Use those executable paths
even when the virtualenv is not on PATH. Validate `cli --version` and `cli --help`; if a recorded
environment was moved, reinstall the skills from the intended executable using `--replace`.
Retain the installed skills root (the parent of this skill directory) with `--dest` for checks and
replacement, especially after a custom-scope installation.
Do not import internal Python modules as an integration API.

Determine the data home from the operator's request, existing MCP registration, or
`LOCAL_RAG_MCP_HOME`, falling back to `~/.local-rag`. Resolve it to one absolute path and use
`cli --home DATA_HOME ...` throughout. Inspect existing client registration without displaying
credential values. For Codex, check the installed `codex mcp --help`, then `codex mcp get local-rag-mcp`.
Only use tools/commands actually available on this machine.

If initialized, run `doctor --json`, `status`, and `source list`. Do not rerun `setup` over an existing
  configuration: it writes initialization settings and can reset selected options. Preserve existing
sources, client entries, credentials, and custom settings. Zero sources is a valid initialized
state; `doctor`/`status` exit `2` until a source is enabled.

## Configure the missing pieces

- On a new data home, `setup --no-ocr` supplies native text extraction and full-text search without
  API keys or downloads. Use `setup --full` when OCR was requested. Explain any resulting OCR
  coverage limit; do not ask the operator to choose every optional feature.
  For an initialized no-OCR install, use `ocr install` to enable requested OCR while retaining its
  settings, then run the authorized `reindex --all --reextract --background` to reprocess affected
  documents. Do not reset the installation with another `setup` call.
- Reuse an existing intended source. If none is specified or available, ask for only the local
  directory or Google Drive root/account needed for retrieval. Never assume the current repository
  is a document source. Derive a stable source name when unambiguous.
- For an authorized local source, validate its absolute directory, run
  `source add-local NAME ROOT`, then `reconcile --source NAME --background`. Poll `jobs status ID`
  until completed/failed, retaining the job ID on interruption. Do not enqueue duplicate work.
- For Drive or optional embeddings, read [references/integrations.md](references/integrations.md).
  Request file paths/account/folder IDs, never credential contents in chat. Browser consent or local
  secret entry is the operator's step; perform the surrounding setup yourself.
- Only install/start the optional OS user service when the operator explicitly requested continuous
  indexing. An ordinary setup request does not opt into that service.

If a source or job fails, use its structured status to fix the actionable cause within scope. Report
the remaining problem without looping through OAuth, indexing, or setup blindly. Do not remove
sources, rebuild all indexes, switch accounts, or enable a remote provider as an incidental repair.

## Connect the agent and prove retrieval

Use the reader profile. For Codex, compare the existing named entry and add/update only this entry
when needed using the installed client's CLI. Substitute the actual absolute paths:

```text
codex mcp add local-rag-mcp --env LOCAL_RAG_MCP_HOME=DATA_HOME --env LOCAL_RAG_MCP_PROFILE=reader -- MCP_SERVER
codex mcp get local-rag-mcp
```

Pass these as separate arguments or quote shell paths safely. The server is the absolute executable
from `runtime.json`. Embedding secrets belong in the protected settings file described in the
integration reference; only the data home belongs in client configuration. Other clients require
their supported stdio registration mechanism; preserve unrelated configuration and report if no
integration mechanism is available.

After reconnect/reload, inspect the actual MCP tools exposed to this agent. Use `doctor`, `sources`,
`search`, then `read` with a returned `document_ref`, using a relevant query from the requested
source. Check provenance and search coverage, including zero hits. A saved registration or a
successful CLI search does not prove that this agent's MCP connection works. If live tools are not
yet loaded, complete CLI verification and state that client reconnect/MCP verification remains;
never simulate tool calls or claim unavailable tools were used.

The installed `local-rag` usage skill teaches ongoing retrieval. If newly installed skills are not
yet in the current client's catalog, read their absolute `SKILL.md` files now and explain any
necessary client reload for future automatic discovery. Finish with source/readiness, verified
CLI/MCP evidence, coverage limits, and only the required remaining operator action.
