# v0.11.0 — Agent RAG service: daemon sync, Drive trash, VPS over SSH

This release turns `local-rag-mcp` into a long-running RAG service for one user. It runs either on
a shared VPS that clients reach over SSH + stdio, or as a private install on one machine. Sources
are local folders and Google Drive. Index data is derived; source files and Drive are never
changed.

## Highlights

- **Serve daemon runs the job queue.** `local-rag-mcp serve` writes a heartbeat and claims queued
  jobs. Other processes, such as MCP over SSH, only enqueue while the daemon is alive, so a
  dropped connection no longer kills an index job. Orphaned queued jobs expire after 20 minutes,
  and no job can run twice. `doctor` adds a non-blocking `daemon` check.
- **Per-source schedule.** Drive is polled every 300 s and local sources every 600 s, and every
  Drive source gets a full reconcile every 12 h. Change these with
  `source set NAME --poll-seconds N --full-reconcile-seconds N`. Sources report
  `last_synced_at` (last success), `last_attempt_at` and `next_sync_at`. `doctor` flags stale
  sources.
- **`refresh` tool and CLI.** Queues one incremental reconcile, at most once per 60 s per source.
  This is the only reader tool that changes state.
- **Drive trash and deletion.**
  - Trashed files, and files under a trashed folder, keep their index, vectors and raw cache but
    are hidden from search, `get_chunk`, coverage and `read`. `read` returns `document_trashed`
    unless `include_trashed` is set. Restoring a file needs no download.
  - Permanently removed files purge their raw cache, unreferenced extracted artifacts and orphaned
    vectors. Local deletions purge artifacts too. Full reconciles garbage-collect orphans.
- **Drive service accounts.** `source add-drive ... --service-account-key PATH`; the key must
  have mode 0600 and its path is hidden. Whether `changes.list` reports files shared with a
  service account has not been verified against live Drive. The 12 h full scan is the safety net.
- **Google Docs as Markdown.** Docs export as Markdown with embedded images stripped, so headings
  become sections. A rejected export falls back to `text/plain`.
- **Reading and browsing.**
  - New `list_documents` tool and `list` CLI, with keyset cursors.
  - `read` caps `length` and `window` at 40000 characters and returns `next_start`.
- **Search quality.**
  - Optional cross-encoder reranker: `rerank` extra, off by default.
  - Eval reports MRR@10 and nDCG@10; see [eval-baseline.md](../eval-baseline.md).
  - Window chunks carry a `title | path` context line for both FTS and embeddings.
- **Formats.**
  - New: HTML, CSV, JSON, EPUB, ODT/ODS/ODP.
  - Optional markitdown for listed extensions (`markitdown` extra).
  - Drive PDFs support `get_page_image` and the integrity check through the raw cache.
  - Spreadsheet cells are rendered as displayed (`5,000,000`, `03/11/2026`, `12.5%`) instead of
    raw `5000000.0` or `2026-11-03 00:00:00`.
  - Drive paths stay readable: only `%`, `/`, `\` and control characters are escaped, so
    `4. QUY TRÌNH THU NGÂN.docx` is no longer shown as `4.%20QUY%20TRI%CC%80NH...`.
- **Layout.** `complex_layout` is now document metadata (`layout_flags`, `layout_pages`) instead of
  an open review, so it no longer keeps `doctor` degraded.
- **Deployment.** [deployment-vps.md](../deployment-vps.md) covers a shared VPS with clients over
  SSH, plus an operator-installed systemd unit for `serve`. claude.ai web and mobile are not
  supported yet, because there is no HTTP/OAuth transport.
- **Cleanup.**
  - One `release.yml` workflow replaces the per-version workflows.
  - `local-rag` is deprecated and will be removed in the next minor release.
  - New `legal_chunking` setting, on by default.

## Upgrade and rollback

Stop the operator-managed `serve` process and disconnect MCP clients for the selected home. Back
up the **entire data home**: SQLite/WAL state, extracted and effective artifacts, revisions,
configuration and protected credentials. Keep the backup private.

Install the verified `phamviet_local_rag_mcp-0.11.0-py3-none-any.whl` in the intended isolated
environment. Do not install the unrelated PyPI project named `local-rag-mcp`. Verify the wheel
against `SHA256SUMS` from this repository's GitHub Release. Refresh bundled skills with
`install-skills --replace`.

- **0.10.x → 0.11.0:** on first startup, schema migrations 10–13 run:
  - `daemon_heartbeat`;
  - `documents.trashed_at`;
  - `chunks.body_hash`, backfilled from `chunk_hash`;
  - open `complex_layout` reviews resolved as `migrated_to_layout_flag`, with `layout_flags` and
    `layout_pages` written to document metadata.

  They use stored data only and make no embedding or Drive calls.
- **Homes on the old default extension list** pick up the new formats automatically. A customized
  list is kept as is.
- **Optional re-extraction:** `reindex --reextract` applies the window-chunk context line,
  Google Docs Markdown and displayed spreadsheet values to existing data. It re-embeds the affected chunks, so with a remote
  embedding provider it costs API calls. Without it, existing chunks keep working.
- **New MCP tools** (`refresh`, `list_documents`) appear only after the client opens a new
  session.

Run `local-rag-mcp --home /absolute/data/home doctor --json`, `status`, and `source list`, and
compare counts to the backup. Then start `serve`; `doctor` shows `daemon: ok`.

To roll back, stop all clients and writers, restore the complete pre-upgrade data-home backup, and
reinstall the previous verified 0.10.1 wheel. **Never run 0.10.x against a database migrated to
schema 13**, and never reverse migrations by deleting schema records.

## Validation

- **Checks:** Ruff format/check, strict mypy (37 source files), compileall, and **269 tests
  passed, 1 skipped** on Python 3.12.
- **Offline test doubles:** all Drive behaviour is exercised with fake backends, and embeddings
  and rerankers with fakes. No live Drive, VPS or model download was used.
- **Local end-to-end:** in a temporary home, `serve` reported `daemon: ok`, `refresh` was executed
  by the daemon, `list` paginated, and search returned `last_synced_at`.
- **MCP over stdio:** `scripts/verify_mcp_stdio.py` passed against a throwaway home.
- **Live Drive:** an OAuth full sync of a real folder (15 Sheets, Docs, Word and PDF files) indexed
  every file and answered cited search.
- **Not yet verified:** live service account visibility, live trash and restore, and an SSH
  deployment.
