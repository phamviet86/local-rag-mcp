# v0.12.0 — Optional Streamable HTTP transport

This release adds an optional Streamable HTTP transport to the MCP server. stdio remains the
default and is unchanged. Index data, schema and source handling are unchanged: there are no new
migrations, and source files and Drive are never modified.

## Highlights

- **Streamable HTTP.** `local-rag-mcp mcp --transport streamable-http` serves the same tools and
  profiles over HTTP at `http://127.0.0.1:8765/mcp` by default. New options: `--host`, `--port`,
  `--path` and `--allowed-host` (repeatable).
- **Bearer-token authentication.** The token is read only from `LOCAL_RAG_MCP_HTTP_TOKEN` (at least
  16 characters), never from a command-line argument. Requests without a matching
  `Authorization: Bearer <token>` receive 401.
- **Safe by default.**
  - The default bind is loopback, with DNS-rebinding protection (an unexpected `Host` header
    receives 421).
  - Binding beyond loopback requires the token, and public host names must be listed with
    `--allowed-host name:port`.
  - The `reviewer` and `admin` profiles over HTTP also require the token. Startup exits with code 2
    when a required token is missing.
  - The built-in server speaks plain HTTP; put TLS in front of it (reverse proxy) for remote use.
    OAuth is not implemented.

## Upgrade and rollback

No data migration. Install the verified `phamviet_local_rag_mcp-0.12.0-py3-none-any.whl` in the
intended isolated environment, verify it against `SHA256SUMS` from this repository's GitHub
Release, and refresh bundled skills with `install-skills --replace`. Do not install the unrelated
PyPI project named `local-rag-mcp`. Existing stdio client configurations keep working without
changes.

To roll back, reinstall the previous verified 0.11.0 wheel. The data home is compatible in both
directions because the schema is unchanged.

## Validation

- **Checks:** Ruff format/check, strict mypy, compileall and **279 tests passed, 1 skipped** on
  Python 3.13, including the new `tests/test_mcp_http.py`.
- **Manual HTTP check:** over a real socket, a request without a token returned 401, a request
  with the token initialized the session, and `--host 0.0.0.0` without a token was refused.
- Not exercised: HTTP behind TLS or a reverse proxy, and clients other than the SDK test client
  and `curl`.
