Google Drive sync now supports arbitrary document titles and exposes indexing gaps to AI search consumers.

- Keep local cache and index identity tied to Drive file IDs; preserve original titles, source URLs and folder relationships. No source document is renamed.
- Continue past individual metadata/download/export/parse/index failures. Retain retry state and cursor safety, avoid false deletion after partial listing, and refresh rename/move metadata safely.
- Return scoped `coverage` warnings with search results (including zero matches), distinguish unindexed/stale/pending files, and provide paginated reader `index_coverage` details.
- Add Drive ID scopes for precise retrieval/reindex targets when names collide.

Validation: 80 tests on macOS and Linux, package/fresh-wheel/MCP checks, and CI across Python 3.11–3.13. An isolated same-VPS live trial of the included Drive implementation indexed 142 documents / 2,376 chunks: all four previously failing slash-title Docs were readable with original metadata, resync was idempotent, and MCP FTS/citations/coverage passed. This release changes version metadata and release tooling after that validated implementation; publication additionally requires successful CI on the exact tagged main commit.

The live trial intentionally used no OCR or embeddings. Of 39 PDFs, 28 lacked native extracted text and need OCR/review for content search. Drive sync success does not imply OCR or vector coverage.

### Upgrade

Back up derived state, install the new wheel in your dedicated environment, then run one full Drive reconcile (`reconcile --source NAME --full`). No raw-cache or database schema migration is required; the first pass refreshes metadata in place and may download existing files once. Use returned escaped paths or stable `id:<folder-id>` scopes. See the [Drive migration/coverage guide](https://github.com/phamviet86/local-rag-mcp/blob/v0.8.0/docs/drive-sync.md) and [deployment guide](https://github.com/phamviet86/local-rag-mcp/blob/v0.8.0/docs/deployment.md).

Attach/install only `phamviet_local_rag_mcp-0.8.0-py3-none-any.whl` or the matching source distribution, and verify against `SHA256SUMS`. The package distribution is `phamviet-local-rag-mcp`; the unrelated PyPI project `local-rag-mcp` is not this project. No PyPI publication or production service upgrade is performed by this release.
